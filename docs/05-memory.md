# Persistent Memory

Devin CLI has no built-in long-term memory store. Persistence is built from files it loads or reads: `AGENTS.md` (always-on rules), hooks (inject context at session start), skills (loaded on demand) and custom subagents. Two separate layers are used.

## Layer 1 — Bot state (`data/bot.db`, SQLite, gitignored)

Source of truth for the trading code. Agents never write here.

| Table | Contents |
|---|---|
| `runs` | job, started_at, finished_at, status, error |
| `signals` | date, symbol, features (JSON), setup signature, win-probability estimate, its lower bound, sample size, score, taken / rejected reason |
| `orders` | client_order_id, alpaca_id, symbol, side, qty, type, status, timestamps |
| `positions` | symbol, entry, shares, initial stop, current stop, R, target, trail state |
| `trades` | closed trades: entry/exit, P&L, R-multiple, exit reason, holding days |
| `equity` | daily equity, cash, peak, drawdown |
| `flags` | kill_switch, paused, reason, set_at |

Alpaca remains the truth for live positions and orders; every job reconciles DB ← broker first and alerts on mismatch.

## Layer 2 — Agent memory (`memory/`, markdown, committed to git)

```
memory/
  README.md              # index + read/write protocol
  state.json             # regenerated by EOD job from bot.db
  strategy.md            # current parameters and rationale
  decisions.md           # ADR-style log: date, decision, evidence, backtest id, status
  lessons.md             # durable learnings, tagged #entry #exit #risk #infra #data
  journal/YYYY-MM-DD.md  # daily review by trade-reviewer agent
  weekly/YYYY-Www.md     # weekly review + compaction of daily journals (see docs/09-weekly-report.md)
  backtests/<id>.md      # params, period, CAGR, maxDD, Sharpe, win%, expectancy, verdict
  packs/                 # size-capped review packs built by Python for AI runs (kept 30 days)
```

Size caps that keep recall cheap (see [11-token-efficiency.md](11-token-efficiency.md)):
- `lessons.md` at most 50 bullets.
- Daily pack ≤ 6,000 characters; weekly pack ≤ 16,000 characters.
- Reviewers read at most the last 4 weekly reviews.

### `state.json` shape

```json
{
  "as_of": "2026-10-05T16:15:00-04:00",
  "mode": "paper",
  "equity": 100000.0,
  "peak_equity": 100000.0,
  "drawdown_pct": 0.0,
  "flags": {"kill_switch": false, "paused": false},
  "open_positions": [
    {"symbol": "MSFT", "shares": 50, "entry": 420.1, "stop": 405.3, "r_multiple": 0.6, "days_held": 4}
  ],
  "last_runs": {"premarket": "ok", "entries": "ok", "manage": "ok", "eod": "ok"},
  "strategy_version": "trend-pullback-v1"
}
```

### Write protocol

- Append-only, dated entries; never rewrite history (corrections are new entries).
- Every lesson or decision cites evidence (trade ids, backtest id, journal date).
- No secrets, API keys, or account numbers.
- `lessons.md` is deduplicated: update an existing bullet's evidence instead of adding a near-duplicate.
- Weekly compaction summarises daily journals so recall stays small.

## Wiring

`AGENTS.md` is a tiny pointer: read `memory/README.md` + `state.json` before analysis and follow the write protocol. `python -m bot.memory context` prints the condensed state and latest lessons for an agent that wants a quick recall.

Retrieval is grep over markdown — sufficient at this scale. If memory grows large, add a SQLite FTS5 index over `memory/`.

## Guardrails

- Agents never modify `bot.db`, live config, or broker code paths unattended.
- Strategy parameter changes go through a reviewed git commit referencing a `decisions.md` entry.
